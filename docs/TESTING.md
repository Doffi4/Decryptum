# Тестирование Decryptum на выдуманных данных

Эти инструкции описывают **тестовый prerelease v1.1.1 / versionCode 8**. Публичный v1.1.0 использует прежний dev-код и прежний генератор. Не переносите в раннюю сборку настоящие пароли: известные ограничения описаны в [SECURITY](../SECURITY.md#known-limitations).

Используйте отдельный пустой тестовый профиль или устройство. Не удаляйте важную установку, не очищайте её данные и не отключайте Play Protect ради теста. При конфликте пакета/подписи остановитесь и запишите безопасный текст ошибки. Участие добровольное; любой шаг можно пропустить.

## Режим разработчика и генератор

1. Создайте и откройте пустое хранилище с новым тестовым master password, который больше нигде не используется. Не сообщайте его автору.
2. На главном экране шесть раз нажмите на название **Decryptum** и введите **Heytest08**.
3. Откройте **Настройки → Разработчик → Тестовые данные**.
4. Укажите число записей (1–5000) и сервисов (1–200, не больше числа записей). Есть пресеты: 100 записей / 70 сервисов, 500 / 200 и 1000 / 200.
5. Нажмите **Посмотреть набор**. Сверьте количество записей, сервисов и примеры количества аккаунтов, затем подтвердите добавление.

По умолчанию получится 500 записей для 200 знакомых сервисов. Количество аккаунтов различается, включая группы по 1, 3, 5 и 7. Логины заканчиваются на `@example.invalid`, пароли общедоступные и тестовые. Часть намеренно слабая или повторяется для локальной проверки; это не рекомендации по созданию настоящих паролей. Каждый новый большой набор получает другие логины.

Это данные с обычными полями CSV, сохраняемые существующим шифрованным импортом; открытый CSV-файл не создаётся. Настоящие аккаунты и входы не выполняются. URL знакомых сервисов служат для группировки/значков. Обычные значки сайтов могут обращаться к сетевым провайдерам; сам генератор сетевых запросов не выполняет. Не считайте этот тест подтверждением полного отсутствия сетевой активности приложения.

Добавление дополняет хранилище, а не заменяет его. Смотрите фактически сохранённое число: при частичном результате сначала проверьте записи. Повторное добавление создаёт ещё один набор. Не используйте очистку дублей, сброс master password или полную очистку на важном хранилище. Dev-код лишь открывает инструменты и не заменяет master password.

## Контрольный набор Security Center

Для воспроизводимых счётчиков используйте **отдельное пустое тестовое хранилище**. Нажмите **Добавить 4 записи для Security Center** один раз. Или создайте эти строки вручную, чтобы проверить интерфейс добавления:

| Сервис | Логин | Пароль | URL / TOTP |
| --- | --- | --- | --- |
| Demo Alpha | demo-user-a | password123 | пусто |
| Demo Beta | demo-user-b | password123 | пусто |
| Demo Copy | demo-user-c | NOT_REAL_TEST_ONLY_7z!V9m#2 | пусто |
| Demo Copy | demo-user-c | NOT_REAL_TEST_ONLY_7z!V9m#2 | пусто, точная копия |

Ожидаются **4 парольные записи, 2 слабые, 2 повторно использующие пароль и 2 дубля**. Счётчики пересекаются; их нельзя складывать в число проблемных записей. Если добавить большой набор или повторить контрольный, итоги изменятся. Security Center не проверяет утечки; ноль находок не гарантирует безопасность.

Найдите запись, откройте её, измените название, сохраните и верните исходное название. Проверьте блокировку и повторное открытие; мастер-пароль никому не отправляйте.

## Контрольный TOTP

Нажмите **Добавить демо TOTP**, затем откройте вкладку TOTP. Альтернатива для проверки ручного ввода: сервис `Demo TOTP`, логин `demo-totp-user`, seed `GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ`. Это публичный SHA-1 seed из RFC 6238, период 30 секунд; приложение показывает 6 цифр. Не сравнивайте их напрямую с 8-значными контрольными кодами RFC.

Проверьте читаемость кода, таймер и смену значения. Запись без пароля не входит в число парольных записей Security Center. Не отправляйте код, seed, QR или содержимое clipboard.

## Autofill, доступность и отзыв

В настройках приложения есть переход к выбору Android autofill provider. Запомните прежний выбор и восстановите его после теста. В Chrome может понадобиться включить использование другого сервиса в **Настройки → Автозаполнение и пароли → Настройки автозаполнения**; названия зависят от версии браузера. Используйте только локальную демонстрационную форму и фиктивные записи. Если локальный файл не вызывает предложение, отметьте `NOT_TESTED`: это не доказывает поломку всего autofill. Не проверяйте на настоящей почте или банке.

По желанию проверьте светлую/тёмную тему, крупный шрифт, клавиатуру и TalkBack. Запишите обрезанный текст, непонятные подписи и действия, которые заняли менее секунды / 1–3 / более 3 / неизвестно.

Для отзыва достаточно версии приложения/Android, модели (необязательно), минимальных шагов, ожидаемого и фактического результата, частоты и трёх важных улучшений. Для autofill полезны браузер и его версия. Любой шаг можно отметить «не проверял». Используйте [форму Issues](https://github.com/Doffi4/Decryptum/issues/new/choose) для обычной ошибки; она публичная. Чувствительные подробности передавайте только через заранее согласованный личный контакт без секретов. Скриншоты и логи не обязательны; raw logcat, vault, экспорт и настоящие данные не отправляйте.

Если случайно использовали настоящие данные, остановитесь и не прикладывайте их. Удалять допустимо только фиктивные данные этого теста; не очищайте важную установку.
