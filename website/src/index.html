A CLEAR DATA BOUNDARY

Local first.
Explicit about the rest.

Your vault lives in the app’s private storage. There is no Decryptum cloud account or cross-device sync.

Read the privacy details ↗
Stays on device

Vault records, TOTP generation and local Security Center analysis.

Can use the network

Site icons can disclose a domain to Google, DuckDuckGo and the site itself. The current favicon setting is not a complete network switch.

Not an encrypted backup

CSV exports can contain passwords, TOTP seeds and private passkey material in readable form. Android backup is disabled.

No bundled analytics

No analytics, tracking pixels or remote crash-reporting SDK was found in the current source.

SECURITY, WITH CONTEXT

Understand the protection.

Encryption is one layer. Device security, unlocking, safe recovery and correct integration boundaries matter too.

STORAGE

An encrypted database

Room uses SQLCipher with a random database key wrapped by Android Keystore.

VAULT SECRETS

A separate encryption key

Passwords, TOTP secrets and private passkey material use AES-GCM with a vault key protected by a master-password-derived Argon2id key.

REALISTIC LIMITS

The device is part of the boundary

A compromised OS or an attacker inside an unlocked process can defeat app protections. Independent security assurance has not been established.

LOCAL SECURITY CENTER

A useful next step.
Not a safety score.

The current source checks weak passwords, exact reuse across accounts and duplicate credentials on your device. Review findings and make changes yourself.

No AI or internet is needed for these checks. Breaches are explicitly not checked; a quiet result does not mean your accounts are safe.

OPTIONAL · DEVELOPMENT ONLY

Local analysis, optional Claude guidance.

Local code finds credential hygiene issues. The debug-only Claude prototype explains four aggregate counts after explicit consent; it does not scan the vault or change credentials. It is disabled in release.

Inspect the outbound contract ↗

Four counts. No vault identities.

Only password-entry, weak-password, reused-password and duplicate-credential counts are sent as vault-derived data.

Passwords, TOTP secrets, private keys, hashes, usernames and domains are not sent by this feature. Anthropic receives IP/timing and transport metadata. Counts can still be sensitive; the response is untrusted guidance.

GOOD QUESTIONS

Before you try it.

Does Decryptum work offline?

The vault, password generator, TOTP and local Security Center work offline. Favicons can use the network. HIBP code exists but is not connected to current checks; optional configured debug Claude requests use the network.

Can I recover my vault if I lose my phone?

A portable encrypted recovery workflow is not implemented or verified. Android backup is disabled. CSV export is readable and is not a safe encrypted backup; full restore, including passkeys and TOTP, needs validation.

Is it ready for my only copy of important credentials?

The current development tree has unresolved release blockers. Keep independent recovery options and test with disposable data first. Existing releases can differ from the source described here.

Does AI see my passwords?

The optional advisor accepts only four aggregate counts, never passwords or secret/identity fields. It requires consent per request, is unavailable without debug configuration and is disabled in release. It is not a breach detector.

What platforms and languages are supported?

The Android app targets Android 8.0+ (API 26). Credential Provider/passkey integration requires Android 14+. App strings are English and Russian. Browser and desktop apps, cloud sync and an iOS app are not implemented.

How do I report a security issue?

Read the disclosure instructions. A private reporting channel must be confirmed by the owner before sensitive reports are sent. Do not post secrets or exploit details in a public issue.
